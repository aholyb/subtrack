# SubTrack — трекер подписок для iPhone

**Дата:** 2026-09-11
**Статус:** утверждён, готов к планированию реализации
**Фаза:** 1 (ручной ввод + каталог + отмена + деньги). Фаза 2 — скан почты — описана в разделе «Вне области» и будет отдельной спекой.

## 1. Задача

Приложение для iPhone, которое показывает все активные подписки пользователя, их суммарную стоимость в долларах за месяц (и за год в скобках) и даёт отписаться от любой из них в один-два тапа.

### Что считается успехом

- Пользователь видит на первом экране, сколько денег в месяц уходит на подписки, без прокрутки.
- Добавление известного сервиса занимает не больше трёх тапов.
- Пользователь узнаёт о списании до того, как оно произошло, а не из выписки.
- Ни одна цифра в интерфейсе не является выдуманной: если точных данных нет, приложение молчит, а не угадывает.

### Ограничения, принятые как данность

- **Отмена подписки программно невозможна.** Ни у Apple, ни у сервисов нет публичного API «отменить подписку пользователя». Приложение доводит пользователя до нужного экрана отмены и фиксирует результат с его слов. Это предел честной реализации.
- **Разработка ведётся на Windows.** Сборка и проверка — через Expo Go на физическом iPhone и Expo Web в браузере. Нативные модули вне набора Expo Go не используются.
- Никаких аккаунтов, серверов и телеметрии. Все данные остаются на устройстве.

## 3. Модель данных

Одна основная сущность. Хранится массивом в AsyncStorage под ключом `subtrack.subscriptions.v1`.

```ts
type BillingCycle = 'weekly' | 'monthly' | 'quarterly' | 'yearly';

type CategoryId =
  | 'video' | 'music' | 'ai' | 'work'
  | 'cloud' | 'games' | 'news' | 'fitness' | 'other';

type PaymentMethod = 'appstore' | 'card' | 'paypal' | 'other';

type Subscription = {
  id: string;                    // uuid
  catalogId: string | null;      // ссылка на каталог; null у своих подписок
  name: string;
  categoryId: CategoryId;

  amountMinor: number;           // 1549 = 15.49 — только целые минорные единицы
  currency: string;              // ISO 4217: 'USD', 'EUR', 'UAH'
  cycle: BillingCycle;

  firstBillingDate: string;      // 'YYYY-MM-DD', локальная календарная дата
  trialEndsAt: string | null;    // 'YYYY-MM-DD'

  paymentMethod: PaymentMethod;
  cancelUrl: string | null;
  note: string;

  status: 'active' | 'canceled';
  canceledAt: string | null;     // 'YYYY-MM-DD'

  reminderDaysBefore: number | null;  // null = не напоминать

  createdAt: string;             // ISO 8601
  updatedAt: string;
};
```

### Два решения, определяющие всё остальное

**Деньги — только целые минорные единицы.** `amountMinor: 1549`, никогда `15.49`. Плавающая точка в деньгах накапливает ошибку при суммировании (`0.1 + 0.2 !== 0.3`), а всё приложение — это сумма денег. Ввод пользователя парсится в минорные единицы на границе формы, отображение форматируется на границе экрана, между ними — целые числа.

**Дата следующего списания и суммы в долларах не хранятся, а вычисляются.** Хранимое поле «следующее списание» протухает каждый раз, когда дата проходит, и требует фоновой задачи для обновления — а iOS не гарантирует выполнения фоновых задач. Вычисление от пары «первое списание + цикл» при каждом рендере всегда даёт верный ответ и не может рассинхронизироваться. То же для конвертации: курс меняется, исходная сумма — нет.

### Даты как календарные строки

Все даты подписок хранятся строками `'YYYY-MM-DD'` и обрабатываются как календарные даты в локальной зоне, без времени. Это полностью снимает класс ошибок с часовыми поясами и переходом на летнее время: «5 марта» остаётся пятым марта независимо от того, где находится телефон и сдвигались ли часы. Момент времени появляется только один раз — когда планируется уведомление.

## 4. Вычисления

### 4.1. Дата следующего списания

```
nextBillingDate(firstBillingDate, cycle, today) -> 'YYYY-MM-DD'
```

Прибавляем к `firstBillingDate` целое число циклов, пока результат не окажется строго позже `today`. Если `firstBillingDate` в будущем — он и есть следующее списание.

**Якорь всегда исходная дата, а не предыдущий результат.** Месячная подписка с 31 января даёт 28 февраля, затем **31** марта, а не 28 марта. Наивная реализация «прибавить месяц к прошлому значению» навсегда схлопывает дату к 28-му числу и начинает занижать даты списаний на три дня. Поэтому: `addMonths(anchor, n * monthsPerCycle)` с однократным прижатием к последнему дню месяца, если дня не существует.

Тестируем: 31 января → февраль (обычный и високосный год), переход через границу года, недельный цикл через смену месяца, дата первого списания в будущем, дата ровно сегодня.

### 4.2. Нормализация суммы

```
periodsPerYear: weekly = 365.25 / 7, monthly = 12, quarterly = 4, yearly = 1
yearlyMinor  = amountMinor * periodsPerYear
monthlyMinor = yearlyMinor / 12
```

Промежуточные значения — вещественные; округление до целых минорных единиц происходит **один раз, на границе отображения**. Округление на каждом шаге даёт расхождение между «суммой месячных» и «годовой суммой ÷ 12», которое пользователь замечает.

Недельная подписка за $1.00 показывается как `$4.35 / мес`, а не `$4.00` — год содержит не ровно 52 недели. Использование 365.25 учитывает високосные годы.

### 4.3. Конвертация в доллары

Источник курсов: `https://open.er-api.com/v6/latest/USD` — бесплатный, без ключа, около 160 валют, включая ₴ и ₽. Ответ содержит `rates` (сколько единиц валюты за 1 USD) и `time_last_update_unix`.

```
usdMinor = amountMinor / rates[currency]
```

Кэш в AsyncStorage (`subtrack.fx.v1`): карта курсов, время загрузки, время обновления у провайдера. Запрашиваем при старте, если кэшу больше 24 часов; при этом сразу рисуем интерфейс на старом кэше и обновляем цифры по приходе ответа.

**Поведение при недоступности API:**

| Состояние | Что делает приложение |
|---|---|
| Свежий кэш (< 24 ч) | Конвертирует молча |
| Протухший кэш | Конвертирует, внизу экрана подпись «курс от 10 сентября» |
| Кэша нет вообще | **Не конвертирует.** Каждая подписка показывается в своей валюте; итог показывается отдельными строками по валютам; баннер «нет курса — итог в долларах недоступен» |

Последняя строка — прямое следствие требования «чтобы приложение не врало». Показать сумму, посчитанную по выдуманному курсу, хуже, чем не показать её вовсе: пользователь принимает по этой цифре финансовые решения. Если все подписки в долларах, кэш не нужен и баннер не появляется.

## 5. Отмена подписки

Сердце приложения и единственное место, где оно взаимодействует с внешним миром.

### Три маршрута

| Способ оплаты | Действие |
|---|---|
| App Store | `Linking.openURL('itms-apps://apps.apple.com/account/subscriptions')` — открывает системный экран подписок напрямую |
| Сервис из каталога | `WebBrowser.openBrowserAsync(cancelUrl)` — страница отмены в аккаунте сервиса |
| Остальное | Экран с текстовой инструкцией и кнопкой поиска «как отменить <название>» |

### Подтверждение

После закрытия браузера приложение показывает лист: **«Отмена прошла?»** с вариантами «Да, отменил», «Ещё нет» и «Напомнить завтра».

**Статус никогда не меняется автоматически.** Приложение не может знать, дошёл ли пользователь до конца формы отмены — сервисы делают многошаговые retention-воронки («останьтесь за полцены», «поставьте на паузу»), и факт открытия страницы ничего не доказывает. Тихо пометить подписку отменённой — значит, перестать напоминать о списании, которое продолжит приходить. Это худший из возможных отказов для такого приложения.

«Напомнить завтра» планирует локальное уведомление на следующий день.

### Архив

Отменённая подписка не удаляется, а получает `status: 'canceled'` и `canceledAt`. На экране архива — список и строка «не платишь $X в год», где X — сумма годовых стоимостей архивных подписок. Формулировка намеренно описывает текущее положение дел, а не «сэкономлено за всё время»: накопительную экономию честно посчитать нельзя, не зная, сколько бы пользователь ещё платил.

Из архива подписку можно вернуть в активные.

## 6. Каталог сервисов

Статический `catalog.json` в репозитории, около 40 популярных сервисов:

```ts
type CatalogEntry = {
  id: string;
  name: string;
  categoryId: CategoryId;
  color: string;               // фирменный цвет для монограммы
  cancelUrl: string | null;
  defaultPlans: Array<{
    name: string;              // 'Standard with ads'
    amountMinor: number;
    currency: string;
    cycle: BillingCycle;
  }>;
};
```

Цены в каталоге — подсказка для поля ввода, а не истина: они устаревают и различаются по странам. Пользователь видит подставленное значение и правит его. В интерфейсе цена из каталога помечена как предзаполненная.

**Логотипов нет — монограмма на фирменном цвете.** Загружать чужие бренд-ассеты юридически сомнительно, а класть 40 PNG в бандл — лишний вес ради узнаваемости, которую буква на цветном квадрате даёт почти так же (как «A» в референсном макете).

## 7. Уведомления

Локальные, через `expo-notifications`. Для каждой активной подписки с непустым `reminderDaysBefore` планируется напоминание на **10:00 локального времени** в день `nextBillingDate - reminderDaysBefore`.

Для подписок в пробном периоде напоминание привязано к `trialEndsAt` и имеет приоритет над обычным — «Netflix: пробный период кончается через 2 дня, дальше $15.49/мес» полезнее, чем напоминание о регулярном списании.

**Ограничение iOS: не более 64 запланированных локальных уведомлений.** Поэтому для каждой подписки планируется **только ближайшее** напоминание, а всё расписание перестраивается при выходе приложения на передний план. Планировать всю серию вперёд — верный способ молча упереться в лимит и потерять уведомления по части подписок.

Если разрешение на уведомления не выдано — приложение работает полностью, на главном экране появляется ненавязчивая строка с предложением включить.

## 8. Экраны

Тёмная тема по референсу `design model.jpg`.

```
Фон            #0A0A0A
Карточка       #141414
Обводка        #242424
Текст          #FFFFFF
Текст вторичн. #8A8A8A
Акцент         #FF3D00
```

Крупные жирные заголовки, карточки со скруглением 16, разделители внутри групп.

1. **Главная** (`/`) — заголовок «Подписки», под ним итог `$47.82 / мес` и `($573.84 / год)`; секция «Скоро спишут» (ближайшие 7 дней); список карточек, отсортированный по дате следующего списания. Карточка: монограмма, название, `$15.49 / мес`, дата списания, бейдж пробного периода.
2. **Детали** (`/subscription/[id]`) — сумма в обеих валютах при необходимости, цикл, следующее списание, пробный период, способ оплаты, заметка; кнопки «Отменить подписку» (акцентная), «Редактировать», «В архив».
3. **Добавление** (`/add`) — поиск по каталогу, выбор плана, дата первого списания, напоминание; внизу «Своя подписка» с ручной формой.
4. **Аналитика** (`/analytics`) — доли по категориям (кольцевая диаграмма) и траты по месяцам за год (столбцы). Обе на `react-native-svg`.
5. **Настройки** (`/settings`) — валюта отображения (по умолчанию `$`), напоминание по умолчанию, дата курса с кнопкой обновления, экспорт в JSON, переход в архив.
6. **Архив** (`/archive`) — отменённые подписки, строка «не платишь $X в год», возврат в активные.

## 9. Структура проекта

```
app/                    экраны expo-router
  (tabs)/index.tsx      главная
  (tabs)/analytics.tsx
  (tabs)/settings.tsx
  subscription/[id].tsx
  add.tsx
  archive.tsx
src/
  domain/               чистая логика, без React
    billing.ts          nextBillingDate, periodsPerYear
    money.ts            нормализация, форматирование
    fx.ts               конвертация, политика протухшего кэша
    notifications.ts    вычисление момента напоминания
  store/
    subscriptions.ts    zustand + persist
    fx.ts               кэш курсов
  services/
    fxApi.ts            HTTP к open.er-api.com
    cancel.ts           три маршрута отмены
    notifier.ts         обёртка expo-notifications
  data/catalog.json
  ui/                   переиспользуемые компоненты и токены темы
```

Граница между `domain/` и остальным — принципиальная: в `domain/` нет React, нет асинхронности, нет обращений к хранилищу. Только функции из данных в данные. Именно там живут все вычисления, где ошибка стоит дорого и незаметна, и именно поэтому они целиком покрываются быстрыми юнит-тестами без моков.

## 10. Тестирование

Разработка по TDD: тест до реализации.

**Юнит-тесты (`src/domain/`)** — основная масса:

- `billing`: 31 января → февраль обычного и високосного года; якорь не схлопывается (31 янв → 28 фев → 31 мар); переход через Новый год; недельный цикл; первое списание в будущем; первое списание сегодня.
- `money`: недельная в месячную; отсутствие расхождения между суммой месячных и годовой ÷ 12; парсинг пользовательского ввода `'15,49'` и `'15.49'`.
- `fx`: конвертация; свежий кэш; протухший кэш; **отсутствие кэша не даёт сконвертированной цифры**; подписки только в USD не требуют курса.
- `notifications`: выбор момента; приоритет пробного периода; отсутствие напоминания при `reminderDaysBefore: null`.

**Компонентные тесты** (`@testing-library/react-native`) — на сценарии, а не на разметку: добавление из каталога, отмена с подтверждением и без, пустое состояние, баннер отсутствующего курса.

**Ручная проверка** на физическом iPhone через Expo Go — то, что Jest не покрывает: переход на системный экран подписок, доставка уведомления, внешний вид на реальном экране.

## 11. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| FX API недоступен | Кэш + подпись с датой; без кэша — режим родных валют с баннером |
| FX API вернул мусор | Ответ валидируется по форме; невалидный игнорируется, кэш сохраняется |
| Нет разрешения на уведомления | Приложение работает; мягкое предложение включить |
| Лимит 64 уведомлений | Недостижим: по одному ближайшему на подписку, пересчёт при активации |
| `cancelUrl` не открывается | Откат на поиск «как отменить <название>» |
| Данные в хранилище повреждены | Схема версионирована (`.v1`); нечитаемая запись не роняет старт, показывается предложение экспортировать и начать заново |
| Валюта неизвестна провайдеру | Подписка показывается в родной валюте и исключается из долларового итога с пометкой |

## 12. Вне области Фазы 1

- **Скан почты (Фаза 2).** `expo-auth-session` + PKCE, Gmail API вызывается прямо с устройства, без бэкенда и без пересылки писем куда-либо. Требует: создания OAuth-клиента в Google Cloud Console пользователем; учёта того, что `gmail.readonly` — restricted scope, а значит публикация в App Store потребует аудита CASA. Модель данных Фазы 1 к этому готова: найденная в письме подписка создаёт обычный `Subscription` с пометкой источника.
- Синхронизация между устройствами, аккаунты, шеринг подписок семьи.
- Пауза подписки (кнопка «Pause» из референса) — сервисы реализуют паузу по-разному или не реализуют вовсе; отдельная сущность ради неё не окупается.
- Публикация в App Store.
